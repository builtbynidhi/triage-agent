# Retrieval evaluation

> Generated by `pnpm eval:retrieval` on 2026-11-20. Do not edit by hand. Every number below was measured.

Policy retrieval is scored on two question sets:

- **Eval-derived (27 questions):** every `must_cite` clause of every case in `evals/cases/`, searched with the raw ticket text exactly as the customer wrote it. This is the set the spec asks for. The spec suggested about 25; the 40 cases yield 27, and all are used rather than a hand-picked 25.
- **Held-out (32 questions):** `evals/retrieval/heldout.yaml`, one or more per policy clause, committed **before** any retrieval was built or measured (see git history). It plays no part in choosing the configuration.

A question is a **hit@4** when a correct clause is in the top 4, the number the agent sees. **MRR@10** rewards ranking the correct clause higher. Latency is the median per query on this machine, with models already loaded.

Configuration chosen by the rule fixed before measuring (best eval-derived hit@4, then MRR, then the cheaper reranker): **hybrid: multilingual-MiniLM-L12-v2 + RRF + no rerank**.

## Setup

- Pipeline: FTS5 (BM25, title weighted 2x) and sqlite-vec (exact KNN, cosine) each return their top 10, merged by reciprocal rank fusion (k = 60). The fused top 10 are reranked, and the top 4 returned.
- Embedding models (all q8, 384 dimensions, run locally on the CPU): `bge-small-en-v1.5` (Xenova/bge-small-en-v1.5), `all-MiniLM-L6-v2` (Xenova/all-MiniLM-L6-v2), `multilingual-MiniLM-L12-v2` (Xenova/paraphrase-multilingual-MiniLM-L12-v2).
- Rerankers: none (fusion order); `heuristic-v1` (fusion score plus query-term coverage); cross-encoder `Xenova/ms-marco-MiniLM-L-6-v2` (q8).
- Chosen retriever ID: `hybrid(Xenova/paraphrase-multilingual-MiniLM-L12-v2@q8/mean, rrf, none)`.
